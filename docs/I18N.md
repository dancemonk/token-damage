# Languages on tokendamage.com

English ships first. Russian is second. Then, one at a time and only with a native reviewer: Japanese (`ja`),
Simplified Chinese (`zh-CN`), Spanish (`es`), German (`de`), Brazilian Portuguese (`pt-BR`).
The CLI stays English.

## The rule

A receipt looks the same in a screenshot from any country. The page around it speaks your language.

**Never translated.** These live in `apps/web/src/fixed.json`, outside `i18n/`, so no translator ever sees them:
- the command `npx token-damage` and the brand name
- the tier marks `≡ ≈ ✶`
- stamps: damage classes (ACT OF GOD, UNINSURABLE…), dispute verdicts (DENIED…), quiz score stamps
- receipt line labels, the legend, the stub labels, sample customer names
- achievement names (ONE LAST FIX…)
- numbers on receipt paper: always `1,183,400,000` and `$809.65`, as in the CLI and the PNG

**Translated.** Everything in `apps/web/i18n/<lang>.json`:
- nav, footer, buttons, hints ("Keep pulling…", "Let go."), the stub note
- `/quiz`: questions, options, explanations, score text. Source lines stay English (they are citations).
- `/method`, `/privacy`, and the `/r` page text

**Adjuster's notes and satire lines** (`notes` in the file) are written fresh by a native speaker, not
translated: a joke that needs explaining is not a joke. Until a language has a note, that note stays English,
key by key, marked `lang="en"` in the page. The note is the one line of the receipt that may change language.

## Files

```
apps/web/i18n/en.json   the schema: every key the site uses
apps/web/i18n/ru.json   same keys, Russian
```

```json
{
  "meta": { "lang": "ru", "locale": "ru-RU", "name": "Русский" },
  "strings": { "home.hint.pull": "Тянем-потянем…", "r.prompt": { "one": "…", "few": "…", "many": "…", "other": "…" } },
  "notes": { "sample.0041": "Вы написали абзац.\nОно прочитало библиотеку.", "iceberg.0": "…" }
}
```

- Keys are `page.id`. No copy lives in HTML templates or TypeScript.
- `{name}` slots must match the English string exactly.
- Counts in page text are plural objects keyed by `Intl.PluralRules` category. English needs `one`/`other`;
  Russian needs `one`/`few`/`many`/`other`. The test knows what each locale needs.
- Note keys are either site notes (`sample.0041`, `quiz.q3`) or core note ids (`family.variant`, e.g.
  `iceberg.0`, the id a share link carries). A note may use only the slots its English note uses. Write it
  so it stays true under the same conditions: `restraint.0` fires only for exactly two sessions.
- Voice rules from `docs/ROASTS.md` hold in every language: dry, no exclamation marks, no meme slang, mock
  the situation and never the person.

## Numbers and dates

Page text uses `Intl.NumberFormat` / `Intl.DateTimeFormat` for the page locale ("1,18 млрд", "сентябрь
2026 г."). Receipt paper does not. Notes on `/r` get slot values from a per-language function in
`apps/web/src/notes.ts` (`slotsRu`): Russian writes "1,18 млрд токенов" and puts other counts after a
colon ("Коммитов: 2"), so nouns always agree with their numbers. A language without such a function shows
English notes on `/r`.

## URLs

The language is in the path and nowhere else: `/`, `/quiz`, `/r` for English; `/ru/`, `/ru/quiz`, `/ru/r`
for Russian. No cookies, no redirect by `Accept-Language` (it breaks share links and crawlers). Every page has
`<html lang>`, `hreflang` alternates for every built language, `x-default` → English, and its own title and
description. The footer links to the same page in each language; on `/r` the link keeps the `#v1.…` fragment.
Share links carry no language: a link opens in the language of the path it was opened on.

## Type

IBM Plex Mono covers Latin and Cyrillic and is self-hosted. Japanese and Chinese fall back to system
monospace (`"Noto Sans Mono CJK JP"`, `"Noto Sans Mono CJK SC"`); no CJK web fonts, they are too large.
`:root:lang(ja)` and `:root:lang(zh-CN)` set `--receipt-scale` so receipts may run slightly smaller.

## Adding a language

1. Find a native speaker who will review it. No reviewer, no language.
2. Copy `en.json` to `<lang>.json`, set `meta`, translate `strings`. Leave `notes` empty or write them fresh.
3. If notes are written, add a slot function for the language in `apps/web/src/notes.ts`.
4. Add the code to `--langs` in `apps/web/package.json` (`build`), and to `LANGS` in the web tests.
5. `pnpm -F @token-damage/web test`: key parity, slots, plurals, notes, one folder per language, hreflang,
   no external hosts, and receipts identical across languages. Missing keys fall back to English and are listed
   in the build log.
6. Check `/` and `/<lang>/` side by side: the receipts must match except for the note.
