# Languages on tokendamage.com

English ships first. Russian is second. Then, one at a time and only with a native reviewer: Japanese (`ja`),
Simplified Chinese (`zh-CN`), Spanish (`es`), German (`de`), Brazilian Portuguese (`pt-BR`).
The CLI stays English.

## The rule

One language per page. `/ru/` is Russian and `/` is English, receipt included: its labels, stamps, sample
names, achievements, verdicts and numbers all follow the page ("1 183 400 000", "809,65 $", «ФОРС-МАЖОР»). Tests
fail if a Russian page shows a Latin word or an English page a Cyrillic one, script-rendered text included.

**Stays as it is in every language:** names. The brand (Token Damage), the command `npx token-damage`,
GitHub, products and models (Claude Code, Codex, Gemini CLI, OpenCode, `claude-opus-…`), organisations and
publications (Google, TrendForce, LBNL, The Climate Brink), file paths, the tier marks `≡ ≈ ✶`, and the language
switcher, which names each language in itself («Русский», English). `apps/web/src/fixed.json` holds only these
names, numbers and ids; every word a visitor reads is in `i18n/<lang>.json`.

**Translated, key by key in `apps/web/i18n/<lang>.json`:** everything else: nav, footer, hints, the stub,
`/quiz` (citations included, org names kept), `/method` (sources described in the page language, links kept),
`/privacy`, `/r`, and the receipt (`receipt.*`, `class.*`, `verdict.*`, `ach.*`, `quiz.stamp.*`). Share links
keep English ids, so every `v1` link decodes in every language.

**Adjuster's notes, asides and jokes** are written fresh by a native speaker, not translated: a joke that
needs explaining is not a joke. Each one rests on something real: a known saying, quotation or city joke, or a
fact from the data (the copy review of 2026-09-24 linked a source for every line). A language that has no note
for an id shows no note there; it never falls back to another language.

## Files

```
apps/web/i18n/en.json   the schema: every key the site uses
apps/web/i18n/ru.json   same keys, Russian
```

```json
{
  "meta": { "lang": "ru", "locale": "ru-RU", "name": "Русский" },
  "strings": { "home.hint.pull": "Тянем-потянем…", "r.prompt": { "one": "…", "few": "…", "many": "…", "other": "…" } },
  "notes": { "sample.0041": "Вы написали абзац.\nОно прочитало библиотеку.", "iceberg.0": "…" }
}
```

- Keys are `page.id`. No copy lives in HTML templates or TypeScript.
- `{name}` slots must match the English string exactly.
- Counts in page text are plural objects keyed by `Intl.PluralRules` category. English needs `one`/`other`;
  Russian needs `one`/`few`/`many`/`other`. The test knows what each locale needs.
- Note keys are either site notes (`sample.0041`, `quiz.q3`) or core note ids (`family.variant`, e.g.
  `iceberg.0`, the id a share link carries). A note may use only the slots its English note uses. Write it
  so it stays true under the same conditions: `restraint.0` fires only for exactly two sessions.
- Voice rules from `docs/ROASTS.md` hold in every language: dry, no exclamation marks, no meme slang, mock
  the situation and never the person.

## Asides

`asides` in a language file holds a few Saint Petersburg lines (`spb.N`), written fresh by a native speaker. Now
and then (about one print in five after the first, at most once per visit, never the same line twice in a row)
one replaces a sample receipt's note on the home page. They never appear on `/r`, in share links, on real
receipts or in the no-JS page; tests assert all four. Topics are the city and its drinking, never drugs, never
brands. Two short lines at most. A language may have none; empty slots are skipped.

## Pool

`pool` in a non-English language file holds that language's rotating lines (`docs/ROASTS.md` §The pool): same ids
and kinds as the English pool in core, written fresh by a native speaker about the same real events, never
translated. The build rejects an unknown id, a changed kind or a satire line without `{share}`, and never falls
back to English lines. The site prints only lines whose sole slot is `{share}` and that have no band. Latin
appears only in names (companies, products, places), which the one-language test allows by name. A page's data
carries only the kinds it prints, in its own language.

## Numbers and dates

Everything, receipt included, uses `Intl.NumberFormat` / `Intl.DateTimeFormat` for the page locale ("1,18 млрд",
"сентябрь 2026 г.", "24.09.26 · 17:38"). Notes on `/r` get slot values from a per-language function in
`apps/web/src/notes.ts` (`slotsRu`): Russian writes "1,18 млрд токенов" and puts other counts after a
colon ("Коммитов: 2"), so nouns always agree with their numbers. A language without such a function shows
no notes on `/r`.

## URLs

The language is in the path and nowhere else: `/`, `/quiz`, `/r` for English; `/ru/`, `/ru/quiz`, `/ru/r`
for Russian. No cookies, no redirect by `Accept-Language` (it breaks share links and crawlers). Every page has
`<html lang>`, `hreflang` alternates for every built language, `x-default` → English, and its own title and
description. The footer links to the same page in each language; on `/r` the link keeps the `#v1.…` fragment.
Share links carry no language: a link opens in the language of the path it was opened on.

## Type

IBM Plex Mono covers Latin and Cyrillic and is self-hosted. Japanese and Chinese fall back to system
monospace (`"Noto Sans Mono CJK JP"`, `"Noto Sans Mono CJK SC"`); no CJK web fonts, they are too large.
`:root:lang(ja)` and `:root:lang(zh-CN)` set `--receipt-scale` so receipts may run slightly smaller.
Stamps: Special Elite (Latin) on English pages; Rubik Mono One (OFL, Cyrillic) on Russian pages, where stamp words
are longer and may wrap. A new script needs a stamp face that covers it.

## Adding a language

1. Find a native speaker who will review it. No reviewer, no language.
2. Copy `en.json` to `<lang>.json`, set `meta`, translate `strings`. Leave `notes` empty or write them fresh.
3. If notes are written, add a slot function for the language in `apps/web/src/notes.ts`.
4. Add the code to `--langs` in `apps/web/package.json` (`build`), and to `LANGS` in the web tests.
   Render its link-preview images: `node apps/web/scripts/og.mjs --langs <lang>` (headline `og.home`).
5. `pnpm -F @token-damage/web test`: key parity, slots, plurals, notes, one folder per language, hreflang,
   no external hosts, and receipts identical across languages. Missing keys fall back to English and are listed
   in the build log.
6. Check `/` and `/<lang>/` side by side: the receipts must match except for the note.
